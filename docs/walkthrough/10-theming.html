Chapter 10

Theming & the Design System

Eight runtime themes, from one elegant trick: every colour is a CSS variable in two forms, so both Tailwind utilities and their opacity modifiers re-theme instantly. Adding a theme is one token block plus one registry line — nothing else changes.

The dual-variable token trick

In styles/tokens.css, every colour token exists twice:

--accent-base: #b5532f;          // hex — for inline styles & SVG fills: var(--accent-base)
--accent-base-rgb: 181 83 47;    // "r g b" channels — for Tailwind

Tailwind's config maps colours to rgb(var(--accent-base-rgb) / <alpha-value>). That single line is why bg-accent-base and bg-accent-base/20 both re-theme — the opacity modifier composes with the channel form. A theme is one :root[data-theme="id"] block that overrides these variables; switching themes is just setting data-theme on <html>. Every class and inline var() across the app cascades from there.

Decision · variables, not a rebuildThemes change at runtime with zero JS recomputation and no flash — the saved theme is applied before first paint in main.tsx. The alternative (Tailwind's dark: variants or multiple built stylesheets) couldn't express six light + six dark palettes cleanly, nor re-theme inline SVG. One source of truth, cascading.

Dark themes set color-scheme: dark, re-point the parchment/ink roles, and lift the status colours (rose/sage) for legibility. Each dark theme sets its own ground depth, chroma envelope and hue drift rather than sharing one lightness ladder with the hue swapped — the grounds span OKLCH L 16–24, so they stay distinguishable from one another.

Decision · darks are pairs, not strangersEvery dark theme already shared an accent hue with one light theme — Ember with Terracotta, Forest Night with Sage Grove, Indigo Night with Lavender, Graphite with Eggshell — because the light set occupies most of the warm spectrum and any warm dark will echo it. Rather than fight that, the darks are now built to it deliberately: each answers its partner's accent hue exactly, and the picker lays them out as couples. What read as derivative reads as a system once it is named. Lantern and Garnet were added to give Mango Sunshine and Rose Quartz partners of their own.

A token --on-accent is the text colour that sits on a filled accent (near-white on dark accents, dark ink on bright ones like Mango's gold) so buttons always read.

Decision · roles, not numbersToken steps are named for what they do (parchment-ground, parchment-surface, parchment-raised, parchment-edge; ink-strong → ink-faint) rather than a 50–300 scale. A numeric ramp inverts incoherently: on a dark theme the “50” step is no longer the lightest, it sits between “100” and “200”, and the numbers stop describing anything. Roles survive the flip.
Decision · elevation is themed tooShadows are tokens, not literals. A warm 5%-opacity shadow is invisible on a dark ground, so a card there would have no edge at all. Light themes keep the soft ink-tinted shadow; dark themes define a card by a 1px ring carried in the shadow’s spread slot plus an inset top highlight. Because the ring rides in box-shadow there is no layout shift and no markup change — shadow-card means the right thing in every theme. The FAB glow follows --accent-base, so it is never a stray terracotta halo around a violet button.
Area colours are never themedThis is a rule: the Bloom's petals use the area's own colour regardless of theme, so the bloom always means the same thing. Themes only change the light around your data.

Cross-device theme sync

The choice is stored per-device in localStorage (applied before paint) and mirrored to the synced settings row so it follows you across devices. The cloud save is debounced (500ms): rapid toggling would otherwise spam the row, and its out-of-order realtime echoes would flicker the selection. Debounce means one save of the settled choice — one echo, equal to what's showing, no flicker.

The area colour palette & picker

36 colours across nine hue families (Greens, Teals, Blues, Purples, Pinks, Reds, Oranges, Yellows, Neutrals). The ColorPicker lays them out in a responsive auto-fill grid (fills landscape width, compact height) in hue order, so contrasting choices sit a glance apart — and it marks colours already used by other areas, so your wheel stays legibly varied instead of collapsing into similar shades.

App-native controls (no OS chrome)

A design goal: the app's experience filters down to every click — no dropping to jarring OS pickers. So the native controls were all replaced with themed, touch-first components:

  • TimeField — a popover time picker (hour / minute / AM·PM), replacing <input type="time">.
  • DateField — a month-grid calendar popover, replacing <input type="date">.
  • SegmentedControl — pill toggles for few choices (time of day).
  • SelectMenu / SortMenu — app dropdowns for many choices (cadence, Home sort), with descriptions.

The "Remind me at" field was also made an obvious tappable affordance (it used to read as empty space).

Motion & the calm boot

  • Framer Motion throughout, wrapped in MotionConfig reducedMotion="user" so prefers-reduced-motion makes every spring instant app-wide.
  • Watercolour wash — a soft accent gradient behind sheets and the ritual player.
  • One boot screen. A static logo cover in index.html (before React), the same logo in the React splash, and the same in the update overlay — so update → reload → boot reads as a single screen that fades to reveal the app. The "Updating Harmony" label only appears on an actual version bump; ordinary reopens show just the logo and land straight on Home with no floor/wait.
  • List reflow: Home's habit list uses layout animation so a card glides into place when the sort order changes (e.g. tapping one done under "Still to do").
